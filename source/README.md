# Palakshi Racer — recovered project

You gave me `palakshi_racer.html`, which is a **compiled production build** (a Vite
"single-file" output — one HTML file with React, Three.js and all your game code
bundled and minified together). That's an important limitation to understand before
using anything in here:

## What's genuinely recoverable

- **`dist/`** — this is the real, accurate build output, just un-inlined back into
  the normal three-piece shape (`index.html` + `assets/index.js` + `assets/style.css`)
  instead of one file. I verified it serves and runs correctly. The control fix
  (right = right, left = left) is already applied in here.
- **`assets/index.js`** has been run through Prettier for readability/formatting,
  but it is still the **minified build**: variable names are single letters
  (`t`, `n`, `r`, `ze`, `_n`...), comments are gone, and React/Three.js/your game
  code are merged into one file. Formatting makes it easier to read and diff —
  it does not and cannot restore the original names or file structure.

## What is NOT recoverable from this file

- Your original multi-file TypeScript source (`src/App.tsx`, `src/game/*.ts`,
  component names, comments, types) **only exists wherever you or another AI
  originally built this** — it is destroyed by the bundling/minification step and
  can't be reconstructed from the output alone. I'm not including a fabricated
  `src/` folder here, since anything I wrote to fill it would be a guess at
  structure, not your actual code.
- `node_modules/` was never something to hand you in the first place — it's just
  your dependencies, regenerated by `npm install` from `package.json` /
  `package-lock.json` on any machine. Shipping it would mean zipping up someone
  else's library code for no benefit.

## What I added so this is still a working project

- `package.json`, `tsconfig.json`, `vite.config.ts` — these match the exact
  template used across your other games in this chat (NEON DRIFT, the earlier
  Palakshi Racer builds, Whiteout, the bear shooter). I reconstructed them from
  that known-identical template, not extracted from the bundle.
- `package-lock.json` — a real lockfile generated from that `package.json`
  against the current npm registry, not fabricated.

## Recommendation going forward

Since this file is a dead end for editing, the best move for future control/physics
or feature tweaks is either:
1. Keep whatever chat/session originally built this version, and make changes
   there where the real `src/` still exists, or
2. Treat `dist/assets/index.js` purely as a reference for *behavior* (what it
   currently does), and re-implement changes against your last known-good
   `src/` tree (e.g. the one from the "palakshi-racer_2.zip" project), porting
   over whatever new features this build added.
